# Performance Baseline: 2026-10-19

- **Status**: First baseline, used to establish the measurement methodology and order of magnitude; not a release commitment
- **Measurement script**: [`packages/runtime/bench/perf.ts`](../../packages/runtime/bench/perf.ts) (`pnpm run bench`)
- **Related requirements**: NFR-PERF-01 (workbench cold start p95 ≤ 1.5s), NFR-PERF-02 (task switching and proof panel p95 ≤ 300ms), 12.2 (latency numbers without measurement conditions are not used as release conclusions)

## 1. Measurement Conditions

| Item | Value |
|---|---|
| Machine | Apple M3 Pro, 12 cores, 36 GB |
| OS | darwin 25.6.0 |
| Runtime | Node.js v22.22.0 |
| Dataset | 20 tasks, ~85 events per task (seeded writes, `seedMs ≈ 5.9s`) |
| Storage shape | **Ledger and derived task summaries only**; workspace scan not included |
| Samples | Cold-start class 15 runs; in-process class 45 runs (task switch) / 15 runs (proof) |
| Cold/warm | Annotated in the table below: `cold` = a fresh process is launched each time; `warm` = repeated operations within the same process |
| Repository version | The first implementation version of this repository (no official tag) |

How to reproduce: `pnpm run bench` (optional `--tasks`, `--samples`, `--events`). The script prints the environment and dataset information required by the table above on its own.

## 2. Results (unit: milliseconds)

| Measurement | Cold/Warm | Samples | min | p50 | p95 | max |
|---|---|---|---|---|---|---|
| `cli.cold-start` (launch CLI to run `doctor`) | cold | 15 | 120.4 | 124.0 | 173.9 | 173.9 |
| `cli.task-list` (list 20 persisted tasks) | cold | 15 | 136.6 | 140.0 | 166.1 | 166.1 |
| `kernel.task-switch` (open task + fold ledger + generate summary) | warm | 45 | 0.9 | 1.1 | 1.6 | 1.7 |
| `proof.open` (re-derive result proof from the ledger) | warm | 15 | 0.1 | 0.1 | 1.2 | 1.2 |

## 3. Against Requirements

- **NFR-PERF-02 (task switching and proof panel p95 ≤ 300ms)**: `kernel.task-switch` p95 = 1.6ms, `proof.open` p95 = 1.2ms. **Meets the target**, but this is data-layer time and does not include rendering.
- **NFR-PERF-01 (workbench cold start to viewing persisted tasks p95 ≤ 1.5s)**: using the CLI as a proxy before the desktop shell, `cli.task-list` p95 = 166.1ms. **Meets the order of magnitude, but strictly speaking is unverified** — see the next section.

## 4. Not Covered and Known Risks

1. **Workspace scan not included**: the cost of `scanWorkspace` is O(number of repository files), and it runs at least once at the start of each task; on large repositories it is very likely to dominate cold-start time. This baseline did not measure it, so it **does not constitute a complete verification of NFR-PERF-01**.
2. **Model calls not included**: the first model round trip for any real task is typically on the order of hundreds of milliseconds to tens of seconds, far larger than the local overhead. This baseline measures only the local path.
3. **Indexing and caching not included**: the project-understanding index and context cache do not yet maintain increments (the implementation of NFR-PERF-03 belongs to P1); currently they are scanned on demand each time.
4. **Desktop shell not implemented**: the final acceptance target for NFR-PERF-01/02 is the workbench; this baseline covers only its shared runtime portion.
5. **Single-machine, single-run sampling**: no multi-machine, multi-run variance analysis was performed; PRD 13.2 requires "repeat each configuration and report variance", which belongs to the evaluation system (P1).

## 5. Conclusion

The local data-layer overhead is two orders of magnitude below the requirements; the bottleneck is not ledger folding, proof derivation, or task opening. The real performance risk is concentrated in two places: **workspace scanning** and **model round trips**. Going forward, an incremental index and baseline dataset should be established for the former first, before discussing a conclusion on meeting NFR-PERF-01.
