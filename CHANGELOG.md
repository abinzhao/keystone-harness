# Changelog

This file records all notable changes to Keystone. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the versioning scheme follows [Semantic Versioning](https://semver.org/) (the kernel, protocol, Schema, and SDK are versioned separately; see Section 4 of [`GOVERNANCE.md`](./GOVERNANCE.md)).

## [Unreleased]

### Added

- **Protocol layer** (`@keystone/schemas`): 88 versioned Schemas and runtime validators, covering the Outcome Contract, Run Event, Capability Lease, Evidence, Proof, Context Plan, Project Fact, Experience, Extension Manifest, and agent interaction objects; canonical JSON encoding, content addressing, and hash chains.
- **Kernel** (`@keystone/kernel`): an append-only event ledger and deterministic state folding, state machine and transition-table validation, Contract compilation/revision/import-export, scope checking, Capability Lease issuance and validation, Provenance propagation, Evidence storage and invalidation, Proof Graph and completion determination, Proof Package rendering, checkpoints and branching (including branch history seeding), recovery validation, Project Fact storage, Experience Firewall, Autonomy Envelope, degradation and orderly exit; `KernelSession` as the sole authoritative write entry point.
- **Tools and verifiers**: file read/write/search, standalone command execution, and read-only git tools, all validated by a Lease first; six verifiers — test / typecheck / lint / build / diff_scope / project_rule — that faithfully declare their evidence level and independence.
- **Model layer** (`@keystone/models`): a BYOK OpenAI-compatible adapter (without pulling in an SDK), a deterministic offline adapter, multi-model routing and fallback, and credential storage (0600, with secrets never entering configuration or logs).
- **Runtime** (`@keystone/runtime`): the Builder Loop and Assurance Loop, Context Plan generation, budget and context pressure, human-intervention determination and request construction, bounded automatic repair, four run modes and degradation evaluation, verification orchestration, the **experience learning closed loop** (generating candidate experience from verified tasks, deciding promotion by source trustworthiness, and after reuse having the Assurance Loop evaluate it independently and immediately degrading on negative transfer), and the **local Run Protocol service** (loopback + token authentication, capability negotiation, task/event/proof endpoints, non-blocking intervention).
- **Extension SDK** (`@keystone/extensions`): Manifest validation and integrity, internal consistency checking, installation review, the conformance suite, the registry, activation gating, and isolation triggers.
- **Reference extension** (`@keystone/extension-no-debug-statements`): a runnable verifier extension, with end-to-end tests spanning declaration, integrity validation, and the conformance suite through to registration/activation/isolation.
- **CLI** (`@keystone/cli`): project onboarding, task execution and queries, pause/stop/resume, branch derivation and comparison, proof viewing and export, state replay, protocol Schema export, model and credential configuration, environment self-check, and the `serve` local service.
- **Workbench** (`packages/runtime/web/workbench.html`): a single-file four-zone workbench with no build step and no dependencies, whose rendering and data have been verified in a real browser. The server injects the message catalog for the resolved language, so the UI is localised too.
- **Localisation** (`@keystone/i18n`): language resolution (`--lang` > `KEYSTONE_LANG` > `config.json#language` > `zh-CN`) and the zh-CN/en catalogs. CLI output, help summaries and the workbench UI are localised; protocol field names, event types, schema paths and proof text stay English, so the hash-addressed proof package remains language-neutral. English is the identity translation (message ids are the English source strings), so a missing entry degrades to readable English rather than a broken token.
- **Cross-platform execution** (`@keystone/kernel`): a pure spawn-target resolver that keeps POSIX shell-free and runs Windows `.cmd` launchers (`npm`/`pnpm`/`yarn`/`npx`) through `cmd.exe` with arguments escaped for it; the child environment allowlist gains the Windows plumbing variables; temporary directories come from the platform rather than a literal `/tmp`; credential file permissions are requested on a best-effort basis. macOS is verified; Windows is implemented and unit tested at the resolution layer but has not been run end to end on a Windows machine.
- **Bilingual documentation**: `README.md` is Simplified Chinese (the default) with `README.en.md` as the English version, cross-linked; every other document is written in English.
- **Performance baseline**: the `pnpm run bench` measurement scripts and `docs/performance/baseline-2026-10-19.md` (including hardware, dataset, sample counts, cold/warm distinction, and explicitly uncovered items).
- **Documentation baseline**: `AGENTS.md`, `CONTRIBUTING.md`, `CODE_OF_CONDUCT.md`, `SECURITY.md`, `GOVERNANCE.md`, `SUPPORT.md`, `ROADMAP.md`, plus ADR-0001..0005 and the architecture description.

### Notes

- There is no formal release version yet; the desktop shell is not packaged (no Tauri packaging, signing, or notarization).
- The end-to-end acceptance tests are in `packages/runtime/test/acceptance.test.ts`: a real Git repository, real failing tests, and real file modifications, verifying that "a model claiming completion does not count as completion", "out-of-bounds writes are rejected before hitting disk", "a failure triggers bounded repair and is eventually fixed", "replay is consistent", and "workspace changes invalidate proofs".
- The learning closed-loop tests are in `packages/runtime/test/learning.test.ts`: verifying that "only provable lessons are promoted", "inferences only enter the quarantine area", and "negative reuse is immediately degraded".
- The Run Protocol service tests are in `packages/runtime/test/server.test.ts`: verifying that "a task cannot be started without a token", "a task started over HTTP can reach proven", and "the proof seen remotely matches the local one".
